# RoadMap

本文件记录 KWDB TSDB Grafana 数据源插件的开发计划。只列已经确定要做的事，不写愿景。

## 当前版本

**v1.2.x** — 已具备提交 Grafana 插件目录审核的条件。

已完成的能力：五种查询编辑器模式（降采样、插值补洞、最新值、窗口事件、原始 SQL）、Grafana 标准时间宏、三层只读防护、KWDB 时序特性全覆盖（`time_bucket`、`time_bucket_gapfill` 五种插值、四类最新值函数、五种窗口函数）、TLS 四种模式、13 项可配置连接参数、表/字段/tag 值浏览、查询型模板变量、单帧 10 万行上限与截断提示。

## v1.3.0 — 发布前收尾

| 事项                          | 状态       | 说明                                                                                                                                                                                                         |
| ----------------------------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| CI 接入全量 plugin-validator  | 已完成     | 之前 CI 只跑 `metadatavalid`，全量校验只在发版流程且从未实跑                                                                                                                                                 |
| 健康检查错误分类提示          | 已完成     | 认证失败、库不存在、超时、TLS 等场景给出人话判断，原始 SQLSTATE 保留                                                                                                                                         |
| 连接参数前置校验              | 已完成     | 端口范围、sslmode 白名单（拒绝 pgx 的 `allow`/`prefer` 静默降级）                                                                                                                                            |
| 变量支持 API 迁移             | 已完成     | `setVariableQueryEditor` 已废弃，改为数据源实例上的 `variables` 属性                                                                                                                                         |
| 核心逻辑单测补齐              | 已完成     | SQL 生成与变量查询解析达到接近 100% 覆盖率                                                                                                                                                                   |
| 修复测试暴露的 12 处缺陷      | 已完成     | 见 `docs/code-quality-2026-10-28.md`                                                                                                                                                                         |
| e2e 补齐最新值/窗口/注解      | 已完成     | 新增 12 个用例                                                                                                                                                                                               |
| 模板变量级联                  | 待做       | `metricFindQuery` 需要调用 `getTemplateSrv().replace()`，否则 `tag_values($schema.$table, $col)` 不生效                                                                                                      |
| 窗口表达式进 SELECT 列表      | 待做       | 目前窗口表达式只在 `GROUP BY`，结果集无法标识每行属于哪个窗口。五种窗口函数在 2026-10-22 的真实库实测中均执行成功，所以这是可用性改进而非正确性修复；改了会动所有窗口查询的输出结构                          |
| `last_row` 时间列一致性       | 大部分已修 | 值与时间错位的问题 2026-10-22 已在 `10.110.105.80:26267` 真机复现并修复（时间列现在跟随 `latestFunc`）。剩下时间列可空时 `last()` 与 `last_row()` 的差异，候选方案 `last_row_ts()`                           |
| `interpolate` 常量模式写法    | 已修       | `'constant'` 不在 KWDB 插值白名单，2026-10-22 真机返回 400；现已改为带引号常量 `interpolate(avg(v), '0')`（KWDB 文档示例形式）并有单测固定                                                                   |
| 真机全功能验证                | 已完成     | 2026-10-29 在 `10.110.105.80:26267/factory`（100 万行表）跑通 SQL 语句级 56 条、Go 后端管线、21/21 e2e、告警全链路，见 `docs/real-server-verification-2026-10-29.md`                                         |
| 真机暴露的 3 处缺陷           | 已修       | ①`none` 聚合在分组模式生成非法 SQL（非聚合列改为进 GROUP BY，窗口函数仍排末尾；gapfill 直接去掉 `none` 选项）②宏在字符串字面量/注释里被展开导致语法错误 ③最新值无 tag 时时间列不在帧首位，Grafana 不认时序帧 |
| TLS 端到端验证                | 待做       | 真机 26267 是明文端口，`verify-ca`/`verify-full` 至今只有单测，无任何端到端证据                                                                                                                              |
| `last`/`last_row` 空值语义    | 待做       | 文档称两者都取最大时间戳行、只在空值处理上有差异；需用可空指标列且末行为 NULL 的场景专项验证，候选方案 `last_row_ts()`                                                                                       |
| `EVENT_WINDOW` 结束条件可达性 | 待做       | 真机观察到结束条件永不满足时静默返回 0 行，与本地 3.2.1 文档"未闭合窗口自动完成"不符；需在编辑器或文档中明示                                                                                                 |
| 降采样 `none` 行数膨胀        | 待做       | 6 小时窗口产出 32,136 行（而非 72 行）。SQL 合法但图表会被打爆；建议从降采样移除 `none` 或改名"原始值"并配提示                                                                                               |
| 窗口区间格式校验              | 待做       | 文档要求 `TIME_WINDOW` 区间 ≥10ms 且只支持 ms~year，`SESSION_WINDOW` 阈值只支持 s/m/h/d/w；编辑器未校验，用户填 `500us` 会拿到数据库报错                                                                     |
| TLS 端到端实测                | 待做       | `verify-ca` / `verify-full` 需要一台开了 TLS 的 KWDB 实例                                                                                                                                                    |
| 告警规则端到端用例            | 待做       | 后端链路已通，但"建规则 → 触发 → 收通知"没有覆盖                                                                                                                                                             |

## v1.4.0 — 发布后专项

| 事项                                                        | 说明                                                                                                                       |

## 长期

- 注解能力增强：目前用 Grafana 默认实现，后续可按 KWDB 的事件窗口做原生注解源。
- 查询性能：连接池参数已有默认值，是否提供按查询类型区分的超时策略需要真实负载数据后再决定。

---

## 不在计划内

以下事项明确不做，避免反复讨论：

- **多语句查询**：后端只读防护刻意拒绝多语句，这是安全边界，不会为了灵活性放开。
- **非时序关系表的专用编辑器**：原始 SQL 模式已经覆盖，关系模型查询走 Text2SQL 侧更合适。
- **Grafana 12 及以下版本兼容**：`grafanaDependency` 为 `>=13.1.0`，不为旧版本做适配。
