# RoadMap

本文件记录 KWDB TSDB Grafana 数据源插件的开发计划。只列已经确定要做的事，不写愿景。

## 当前版本

**v1.3.0** — 已具备提交 Grafana 插件目录审核的条件。

已完成的能力：五种查询编辑器模式（降采样、插值补洞、最新值、窗口事件、原始 SQL）、Grafana 标准时间宏、三层只读防护、KWDB 时序特性全覆盖（`time_bucket`、`time_bucket_gapfill` 五种插值、四类最新值函数、五种窗口函数）、TLS 四种模式、13 项可配置连接参数、表/字段/tag 值浏览、查询型模板变量、单帧 10 万行上限与截断提示，以及在真实 KWDB 实例上完成的全功能验证（含 TLS 专项）。

## 发布前仍需完成（仓库外决策）

以下事项不阻塞代码合并，但在提交 Grafana 插件目录审核前必须定案：

- **插件 ID 与仓库归属（2026-10-29 修订）**：插件 ID 为 `kwdb-tsdb-datasource`，采用校验器要求的 `org-name-type` 三段式。v1.4.0 采用的 `kwdb-datasource` 只有两段，提交目录审核时被判为 `invalid-id-format`，因此改回三段式；`kwdb` 对应公司 Grafana Cloud 组织。仓库将从个人账号迁移到 `KWDB` GitHub 组织。插件 ID 进入目录后不可更改。
- **签名 token**：`GRAFANA_ACCESS_POLICY_TOKEN` 尚未配置到仓库 Secrets，release 产物目前未签名。首次提交审核可以不带签名，但审核通过后的每个版本都必须签名。
- **分支保护**：main 目前没有 required status checks / required review，CI 结果只是建议而非门禁。

## 长期

- 注解能力增强：目前用 Grafana 默认实现，后续可按 KWDB 的事件窗口做原生注解源。
- 查询性能：连接池参数已有默认值，是否提供按查询类型区分的超时策略需要真实负载数据后再决定。

---

## 不在计划内

以下事项明确不做，避免反复讨论：

- **多语句查询**：后端只读防护刻意拒绝多语句，这是安全边界，不会为了灵活性放开。
- **非时序关系表的专用编辑器**：原始 SQL 模式已经覆盖，关系模型查询走 Text2SQL 侧更合适。
- **Grafana 12 及以下版本兼容**：`grafanaDependency` 为 `>=13.1.0`，不为旧版本做适配。
